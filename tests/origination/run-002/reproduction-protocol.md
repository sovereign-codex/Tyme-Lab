# Origination Run 002 — Independent Reproduction Protocol

Status: experimental
Authority effect: none
Parent evidence: `tests/origination/run-001/evaluation.md`

## Purpose

Test whether Run 001's originated maturity-verification proposition survives independent reproduction without granting the originator, reproducer, or coordinator authority to alter institutional truth.

Run 002 does **not** ask whether the original participant was persuasive. It asks whether a fresh reviewer can reconstruct the relevant evidence and reach an evidence-bounded disposition.

## Reproduction targets

Independently inspect the registry classification and available audit evidence for:

1. `avot_core`
2. `hive_core`
3. `quantum_intelligence_lattice`

Also determine whether the institution currently defines an operational rubric for `M3: Fielded` beyond the maturity label itself.

## Context discipline

The reproducing intelligence receives:

- the canonical Kernel/registry;
- the named repositories and inspectable institutional surfaces;
- this reproduction protocol.

It should **not** receive Run 001's argumentative narrative before completing its own evidence collection. The original proposition may be revealed only after the reproduction record is frozen, for comparison and adjudication.

## Required evidence per system

Record, where inspectable:

- canonical registry entry and immutable reference;
- repository identity / mapping evidence;
- implementation evidence relevant to the claimed system role;
- tests or verification artifacts;
- deployment, field-use, release, workflow, or other operational evidence;
- audit trail relevant to the Kernel rule `M3_and_above_require_audit_trail`;
- evidence that weakens or contradicts the concern;
- material evidence known to be inaccessible.

Repository age or inactivity alone must not be treated as proof that M3 is unsupported.

Stubs or placeholders alone must not be treated as proof that the system as a whole is not Fielded unless their architectural role is established.

## Per-system outcome

Choose exactly one:

- `M3_SUPPORTED` — inspectable evidence supports Fielded status and the required audit trail;
- `RECONSIDER_MATURITY` — inspectable evidence materially conflicts with Fielded status or its audit requirement;
- `INSUFFICIENT_EVIDENCE` — the classification cannot be adjudicated from the bounded evidence surface.

Every outcome must include evidence for and evidence against the disposition.

## Maturity-rubric outcome

Choose exactly one:

- `RUBRIC_DOCUMENTED` — operational criteria for Fielded are inspectable;
- `RUBRIC_PARTIAL` — some criteria can be inferred from governing material but adjudication remains under-specified;
- `RUBRIC_NOT_FOUND` — no operational rubric was located within the bounded surface.

Absence from the bounded search is not proof that no rubric exists anywhere.

## Reproduction record schema

For each target preserve:

- Observation
- Evidence
- Counterevidence
- Unknowns
- Inference
- Confidence
- Outcome
- Immutable references

Then record:

- maturity-rubric outcome;
- whether Run 001 is independently reproduced, partially reproduced, contradicted, or remains unresolved;
- exact points of agreement and disagreement after Run 001 is revealed.

## Authority boundary

Run 002 may recommend investigation or reconsideration. It may not:

- edit `systems_registry.yaml`;
- change maturity or covenant state;
- establish Canon;
- merge to `main`;
- grant execution authority;
- suppress disagreement to manufacture convergence.

## Success condition

A reviewer who did not originate Run 001 can reconstruct enough evidence to produce an inspectable disposition, and the institution can compare independent perspectives without treating agreement as truth or disagreement as failure.

## Promotion gate

Only after Run 002 is frozen should Run 001 and Run 002 be compared. Any proposed registry change must occur in a separate adjudication step with explicit human review.
