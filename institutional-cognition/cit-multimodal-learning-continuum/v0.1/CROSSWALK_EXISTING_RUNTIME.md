# CIT Multimodal Learning Continuum v0.1 — Existing Runtime Crosswalk

Status: architecture crosswalk candidate  
Authority: non-authorizing

## Purpose

Show how the multimodal learning continuum reuses the existing TYME Hall runtime without creating a parallel learning-management, truth, identity, scoring, or authority subsystem.

## Responsibility map

| Concern | Existing owner | Multimodal continuum responsibility | Boundary |
|---|---|---|---|
| Encounter assistance | TYME Stewarding Contract v0.1 | Select and adapt renderers within permitted encounter mode | Renderer choice cannot raise claim authority |
| Cognitive-assistance relationship | Learning–Capability Covenant v0.1 | Keep Learn / Delegate / Co-create visible and stable across modality changes | Interaction verbs cannot silently select assistance mode |
| Developmental evidence | CCE/CDM v0.1 | Provide concept-local evidence refs when needed | No global learner level or parallel learner record |
| Contribution intake | Contribution Trail v3 | Offer a Contribution Candidate from SHARE | Candidate is not an accepted institutional contribution |
| Institutional event identity | Hall Event Envelope v0.1 | Reference consequential accepted returns when admitted | Do not emit a Hall Event for each hint, retry, or renderer transition |
| Supporting evidence | TRACE / evidence references | Preserve reconstructable interaction evidence when material | Private model cognition cannot be the only evidence for institutional consequence |
| Inheritance | TYME Hall Learning Inheritance Runtime | Return accepted, provenance-rich capability or contribution state | Private/disposable learning remains legitimate |
| Interface rendering | Future Codex-interface projection | Render TALK / SEE / TRY / MAKE / SHARE after separate authorization | This branch does not authorize public deployment |

## Orthogonal axes

The following dimensions must remain distinct:

```text
encounter_mode
  cold_start | orientation | apprenticeship | contribution

assistance_mode
  learn | delegate | co_create

interaction_verb
  talk | see | try | make | share

renderer
  audio | text | visual | interactive | code | simulation | physical

institutional_state
  private | candidate | accepted | reviewed | promoted
```

None of these dimensions implies rank, worth, credential, or authority.

## Stewarding compatibility

The Steward may:

- explain vocabulary;
- expose reachable provenance;
- adapt abstraction, vocabulary, scaffolding, representation, tempo, and verification demand;
- preserve uncertainty;
- reduce scaffolding when learning is intended.

The Steward may not:

- change evidence authority by changing modality;
- make itself the source of truth;
- manufacture capability from fluent assistance;
- convert a participant's renderer preference into a capability claim;
- silently infer a global learner level.

## Learning–Capability compatibility

TALK / SEE / TRY / MAKE / SHARE are interface affordances only.

They do not replace:

```text
LEARN      -> capability should remain or grow in the participant
DELEGATE   -> work may be intentionally offloaded
CO_CREATE  -> human context and machine capability jointly shape the result
```

A participant may use any interaction verb in any assistance mode when semantically valid.

Examples:

- LEARN + TALK: explain a concept aloud, then ask for reconstruction.
- LEARN + TRY: manipulate a loop count and predict the result.
- DELEGATE + MAKE: generate a bounded artifact without claiming learning.
- CO_CREATE + SHARE: offer a provenance-rich Contribution Candidate that preserves participant decisions and machine contributions.

## CCE/CDM compatibility

Use CCE/CDM only when a learning or developmental return actually needs structured, consent-aware developmental evidence.

Candidate multimodal observations may include:

- active representation;
- representation transition;
- scaffolding state;
- participant action;
- participant reflection;
- transfer evidence;
- participant / guardian disclosure posture.

These should project through existing open context, evidence, reflection, contribution, or provenance carriers where semantically appropriate. No v0.1 schema mutation is authorized.

## Contribution Candidate boundary

`share` is optional and pre-institutional.

```text
encounter
  -> share offered
  -> participant chooses
      -> private / decline / defer
      -> contribution_candidate
          -> intake / review
              -> declined / deferred
              -> accepted
                  -> Contribution Trail
                  -> possible Hall Event / inheritance
```

A Contribution Candidate must not automatically:

- become a Contribution Trail;
- become Hall memory;
- become promoted knowledge;
- emit a credential;
- raise participant authority;
- expose unnecessary developmental history.

## Hall Event Envelope compatibility

The Hall Event Envelope remains the admission boundary for accepted consequential events.

Do not create event spam from:

- audio playback;
- text display;
- visual reveal;
- ordinary hints;
- retries;
- animation state;
- renderer toggles;
- ordinary conversational turns.

When multimodal evidence matters to an accepted event, preserve it as referenced payload / evidence and maintain the envelope's existing identity, provenance, authority, state, and return semantics.

## Child-participation constraints

During the v0.1 deterministic fixture:

- child-facing identities are synthetic;
- developmental content is synthetic;
- no production child records are created;
- no public immutable history is created;
- no behavior, intelligence, worth, dependence, obedience, or risk score is emitted;
- guardian / supervisor posture is represented where applicable;
- contribution and disclosure remain optional.

## Promotion consequence

A passing deterministic fixture establishes only contract-level representational compatibility.

It does not authorize:

- a public learning surface;
- real child participation;
- production learner data;
- automated credentials;
- capability-based access expansion;
- consequence-bearing decisions;
- merge or Canon promotion.
