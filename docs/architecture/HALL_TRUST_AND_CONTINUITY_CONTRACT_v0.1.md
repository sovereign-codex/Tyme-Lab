## 2. Hall functions and site topology

### 2.1 Institutional Hall

Reference entry: `https://tymehall.org/`.

This is the canonical public projection, not the source of institutional authority. Its foyer retains PUBLIC FOYER / NON-AUTHORIZING / INTENT ROUTING. Office, Scrolls, Laboratory, Constellation and Contribution remain the inherited public relationships.

Rendering a claim does not validate it or promote it to Canon. Publishing experimental work does not validate its empirical mechanism. The public Office reports approved state without exposing private deliberation, credentials, sensitive participant data, private references or operational security configuration.

### 2.2 Contributor / Local Hall

The ChatGPT-hosted Reconstruction Probe 001 is a reference candidate for contributor orientation, not a proven local runtime. Its experimental/non-canonical notice remains necessary.

A Contributor Hall supports participant intent, chosen intelligence, drafts, learning, experiments, explicit preview, private exit and proposed returns. It is not a second Canon, an automatic admission gate, or an identity provider merely because it hosts a session.

Participant control, provider hosting, local storage and local inference are separate properties. Privacy, persistence, exportability, offline operation and local inference MUST each have evidence or be marked UNKNOWN/NOT IMPLEMENTED. Neither a website shortcut nor a provider-hosted page establishes any of those properties.

### 2.3 Route and origin decisions

| Function | Reference / proposed placement | Boundary |
| --- | --- | --- |
| Public institutional orientation | Existing `tymehall.org` entry and public relationship paths | Anonymous reading; approved projection only |
| Contributor reference experiment | Existing ChatGPT Reconstruction Probe | Label provider hosting and experimental status; no assumed private/local storage |
| Future participant workspace | Separately reviewed origin or participant-controlled deployment | No host is provisioned by this proposal; do not place untrusted executable experiments beside institutional sessions |
| Governed intake or execution | Separately authorized server-side adapter | Validate every protected operation; no privileged credentials in browser/model context |
| Private Office and incident evidence | Existing authorized private stores | Not exposed by a public route or provenance link |

Paths are navigation, not browser security boundaries. Two paths on one origin share origin-scoped storage. A separate origin is useful isolation, but sibling subdomains alone do not prevent domain-cookie sharing or cross-site request forgery. Any future authenticated workspace needs host-scoped secure sessions, explicit cross-origin policy, request-forgery protection, server-side per-resource authorization and separately bounded service-worker scope. CORS is not authorization.

Do not embed privileged contributor tools in the public foyer or transfer secrets in query strings, deep links, exported evaluation packets or inter-window messages. Prefer ordinary links with clear destination notices; no automatic transfer of participant context.

No third website, redirect, DNS record, iframe integration or new login flow is authorized here. The existing public entry should remain stable while participant implementations evolve separately.

### 2.4 Supporting environments

Branch Laboratory retains reversible experiments; Observation/Drift compares declared and observed state without repair; Containment holds Silver/EchoReversal research; Evidence/Temporal Provenance holds TRACE/TimeBinder lineage; Sovereign Execution makes compute replaceable within existing Work authority.

## 3. Reading is not submitting; assertion is not permission

Anonymous public reading and orientation MUST NOT require an actor envelope, credential, permanent participant profile or acceptance of contributor admission. Authentication is applied only where the operation actually requires it.

A proposed event seeking protected data, institutional intake or execution follows:

```text
Participant -> existing Actor + Authority Envelope
-> independent authentication / verification where required
-> admission policy -> disposition -> bounded Work or observation
-> TRACE / TimeBinder evidence -> review -> approved projection, if any
```

The envelope MUST retain `authority.effect: none` and pass the inherited structural and semantic validator. It asserts context; it does not authenticate its own issuer or grant execution. Do not invent a second authority schema or replace inherited actor, surface and timestamp grammars.

Authentication, delegation verification, expiry, revocation, target/resource scope and Work authorization MUST be checked outside model prompting at each protected operation. A provider session, signature, branch, tool listing, confident answer or institutional title is not permission.

Disposition names in this proposal are descriptive, not a new adopted wire enum. Missing proof results in rejection, quarantine, observation-only or routed review under existing admission rules. Bounded execution requires an independently valid grant. High-impact operations retain explicit approval gates.

Requested action, attempted action, recorded receipt and verified side effect MUST remain separate. Canon, publication, governance, destructive actions and security-authority changes retain their inherited human/institutional gates.

## 4. Capability declaration and data boundaries

Before protected interaction, an adapter declares provider/runtime and version where knowable; exposed tools; requested action/target; network egress; storage location and retention; data visibility; creation, persistence and export capability; credential scope/revocation; and known gaps.

Observed capabilities are not inferred from a brand name. Browsing, authenticated repository access and Office access are separate. Creating a file does not prove persistence or export. A local model does not prove a local corpus.

Private workspace content remains private unless the participant selects a bounded return. Explicit consent is required before new transmission or persistence. Capability disclosures must explain when an action leaves the device/provider. Secrets and unnecessary personal data MUST NOT enter model prompts, public assets, traces, packets or repository examples.

Audit metadata should be minimized. Sensitive payloads belong in approved private stores with access controls and retention policy; public reports use reviewed redacted references. Append-only lineage is not permission to preserve or publish personal content indefinitely. Corrections and authorized retention/deletion actions need traceable metadata rather than silent historical rewriting.

## 5. Silver Agent

Silver is a proposed, non-retaliatory defensive observer. It may classify suspicious input, identify privilege-escalation attempts, recommend isolation/rate limits/minimal disclosure, and return evidence for review.

Silver MUST NOT grant authority, declare Canon, expand its tools, change production authorization, expose protected configuration, invent credentials, retaliate or conduct offensive probes.

Model classification is advisory. Deterministic enforcement remains independent of Silver. Unavailable or uncertain classification MUST NOT relax an enforced boundary. Silver is not a promised defense against every prompt injection or unknown exploit.

## 6. TRACE, TimeBinder and uncertain execution

TRACE preserves `event -> actor -> implementation/runtime -> capability -> verified grant -> target -> action -> result -> evidence -> review`.

TimeBinder preserves asserted occurrence time separately from independently observed receipt time, grant validity intervals, source sequence/causal parents, supersession/revocation and the state interpretation used for a decision. Use inherited canonical UTC timestamp rules. Cross-source clocks do not establish a universal total order; uncertainty is preserved.

A conforming state-changing adapter MUST implement tested replay/duplicate protection, or withhold that capability. An idempotency key is scoped to actor, action, target and intent; a conflicting payload under the same key is rejected or quarantined. Grants are rechecked at execution, not only at initial intake.

A unique receipt row alone does not prove exactly-once external execution. The adapter must address concurrent requests and crashes between admission, downstream effect and result persistence. Use downstream idempotency or transactional coordination where supported. Otherwise an uncertain outcome enters reconciliation with no blind automatic retry. Do not claim an atomic guarantee across systems without evidence.

A receipt without verified side effect is **receipt recorded / execution unverified**. Superseded or revoked instructions are not revived by replaying their artifacts. Cryptographic integrity, when actually verified, is not proof of permission, truth or trustworthy wall-clock time.

TimeBinder Alpha's historical reporter scaffold is not production evidence for any of these controls. TRACE/TimeBinder record evidence; they do not become new authorization authorities.

## 7. EchoReversal and Zero-Day Admission

EchoReversal stays in containment: bounded forensic replay, comparison, divergence reconstruction and reversible recovery proposals. It does not rewrite source history, remediate production autonomously or test adversarial payloads on live services under this contract. Knowledge may leave containment after review; capability does not automatically leave it.

**Zero-Day Admission** is an internal first-contact evaluation label for unfamiliar participants, models, agents, integrations, files or projections. It is not a claim of protection against cybersecurity zero-day vulnerabilities.

```text
Observe -> identify -> bound -> isolate where required -> synthetic test
-> TRACE -> TimeBinder -> drift review -> policy/human disposition
-> limited capability only if separately approved
```

An emergency claim, recycled grant or plausible institutional document cannot escalate authority. For a suspected real compromise, accountable incident handling governs containment, evidence preservation, access revocation, patch/provider guidance and recovery. No counterattack is authorized.

## 8. Two release gates, not one expanding launch dependency

### P0: public read-only orientation

P0 requires an accurate/non-authorizing public role; accessible anonymous reading; truthful state and provenance; no private-data exposure; working essential routes; source/deployment attribution; and clear limits/fallbacks. It does not require a completed Silver, TimeBinder or authenticated contributor runtime.

A missing optional contributor feature is not automatically a P0 blocker when it is honestly marked unavailable. A falsely advertised feature, exposed secret or unsafe enabled action is a blocker for the surface carrying it.

### C1: authenticated intake, persistence or agent execution

C1 remains disabled until its separately authorized implementation demonstrates server-side least privilege; scoped/revocable credentials; target/action allowlists; step-up approval; input/output validation and safe rendering; resistance to untrusted content acquiring tool authority; privacy/consent controls; quotas/cost limits; telemetry and disable path; replay handling; grant freshness; dependency/patch review; recovery practice; and an accountable incident decision holder.

Public reading must survive C1/provider failure without obtaining broader permissions. Edge protections may help, but actual configuration and action-level enforcement need evidence. Documentation or successful deployment is not a runtime security test.

## 9. Accessibility and participant control

Public reading, legible mobile navigation, text/non-voice fallback and an accessible route to essential state are P0 requirements. Review keyboard/focus, screen-reader labels, contrast, zoom/reflow, motion and low-bandwidth behavior using appropriate browsers/assistive tools; text retrieval alone cannot certify visual accessibility.

Contributor designs preserve learn/delegate/co-create distinctions, explicit preview, private exit, retention disclosure and export where actually supported. They must not penalize declining contribution or conflate delegated completion with learned capability. Current CIT candidate restrictions remain controlling until separately revised.

An external provider's login, subscription, memory or mobile constraints must be disclosed rather than described as participant sovereignty by default.
